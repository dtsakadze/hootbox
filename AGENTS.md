# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository.

Hootbox is an open-source, self-hostable feedback collection app: an embeddable widget, a public board with voting and a roadmap, and a team inbox. MIT licensed. A future hosted/paid edition builds on top of it via `ee/` (see `docs/extending.md`).

## Writing style (applies everywhere)

- **Never use the em dash character (U+2014) anywhere**: code, comments, UI copy, docs, commit messages, PR descriptions, seed data. Use a colon, comma, period, semicolon, parentheses, or a plain hyphen instead. Before committing, `git grep -n $'\xe2\x80\x94'` must print nothing (works in bash and zsh).
- UI copy is friendly and playful but short. No jargon in user-facing text.

## Commands

```bash
pnpm dev            # dev server on http://localhost:3000
pnpm test           # vitest against a real Postgres test DB (TEST_DATABASE_URL)
pnpm typecheck      # tsc --noEmit
pnpm lint           # biome check   (pnpm format to auto-fix)
pnpm build          # production build to .output/
pnpm db:generate    # new migration after editing src/server/db/schema.ts
pnpm db:migrate     # apply migrations
pnpm db:seed --reset  # wipe + demo data (demo@hootbox.dev / hootbox123)
```

Before committing: `pnpm typecheck && pnpm lint && pnpm test` must all pass.

## Stack

TanStack Start (React 19, SSR, file-based routes) on Nitro, PostgreSQL via Drizzle ORM + postgres.js, Tailwind CSS v4, zod v4, Vitest, Biome. Package manager: pnpm.

## Architecture rules

- **Layers:** routes → server functions (`src/server/functions/`) → services (`src/server/services/`). Server functions only do auth, access checks and input validation, then call a service. Business logic lives in services, never in routes or components.
- **Validation:** all input schemas live in `src/lib/validation.ts`. Server functions use `.validator(validate(schema))` (not the deprecated `.inputValidator()`). Throw `AppError` (`src/server/lib/errors.ts`) for user-facing errors; anything else is masked as a generic error by the middleware in `src/start.ts`.
- **Access control:** every project-scoped server function calls `getProjectForUser(userId, projectId)` first. Destructive or settings actions check `assertRole(role, "admin")`.
- **Client-safe code:** `src/lib/` is imported by the browser. Never import `src/server/**` or drizzle from there. Enum constants live in `src/lib/constants.ts`.
- **Public endpoints** go under `src/routes/api/` with their own CORS handling. Server functions are same-origin only (CSRF middleware).
- **Extensions:** hosted-edition behaviour (limits, sign-ups, quotas) goes through hooks in `src/server/extensions.ts`, never `if (hosted)` branches in core code. If a new hook is needed, add it to `extensions.ts`.
- **Schema changes:** edit `schema.ts`, run `pnpm db:generate`, review the SQL, commit the migration.
- **Widget:** `public/widget.js` is plain JS with no build step. Keep it dependency-free, Shadow DOM only, and set user/server text with `textContent`, never `innerHTML`.

## Testing

- Tests use the **real database**; do not mock the DB. Each test starts from truncated tables (`tests/setup.ts`).
- Test services directly (`tests/*.test.ts`), including permission checks and concurrency where relevant.
- Use `127.0.0.1` rather than `localhost` in database URLs; `localhost` caused intermittent connection stalls.

## Gotchas

- Biome's `--unsafe` fixes can silently change React effect dependency arrays and remove non-null assertions. Avoid `--unsafe`, or review its diff.
- TanStack Router search schemas: a zod `.transform()` makes the router redirect to normalise the URL. For public pages, keep raw values and interpret them in the component.
- `src/routeTree.gen.ts` is generated by the dev server/build; don't edit it by hand.
- `notes.md` is a local, git-excluded file for the maintainer. Don't commit it.
